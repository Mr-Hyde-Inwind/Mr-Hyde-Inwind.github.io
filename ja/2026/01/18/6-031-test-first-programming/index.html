ついでにブログの記事数を稼いで、ブログ内容を充実できると思います（笑）。

徹底的、無計画的な、ランダムなテストしないように

  1. 正確的なテスト
  2. 綿密的なテスト
  3. 小さいテスト

いいテストスイートの書き方

  1. 入力領域を分割し、各領域から代表値を選んでテストケースとする
  2. 境界値のテストケースを作成する
  3. モジュールを別々でテストする
  4. 他のモジュールに依存するオブジェクトをテストするとき、Stubを使う

test-first programming / TDD

test-first programming もしくは TDD の実施手順は周知されていると思います。

  1. 関数仕様を書く
  2. 関数仕様を踏まえて、テストケースを書く
  3. 関数を実装し、テストをパスさせる
  4. 関数をリファクタリングする

これは一回切りの手順ではなく、各ステップを行き来する必要があるため、完璧な実装を求めて時間をかけすぎないように注意してください。

ベイビーステップで進めるために、以下の手順を検討してみてください

  1. 関数仕様の一部を書き、テストケースを実装し、仕様に定義されている部分を実装する
  2. 入力領域の重要な一部を選択し、シンプルで小規模なテストスイートを実装する
  3. テストをパスする単純な実装から始め、徐々に洗練された実装へと改善していく
